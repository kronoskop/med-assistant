# llm-gateway Specification

## Purpose

Описывает вызов локальной MedGemma в LM Studio: только локальный endpoint, настраиваемый идентификатор модели, таймауты и ошибки, если сервер или модель недоступны.

## Requirements

### Requirement: Только локальный LM Studio
Система SHALL отправлять запросы генерации только на настроенный OpenAI-совместимый базовый URL LM Studio. Система MUST NOT вызывать публичные облачные LLM API (OpenAI, Google, Anthropic и аналоги) для чата.

#### Scenario: Запрос уходит локально
- **WHEN** принят корректный запрос чата
- **THEN** запрос генерации отправляется на настроенный базовый URL LM Studio
- **THEN** генерация чата не отправляется публичному облачному провайдеру LLM

### Requirement: Настраиваемый идентификатор модели
Система SHALL запрашивать генерацию с настроенным идентификатором модели. Идентификатор по умолчанию SHALL быть `med-gemma-1.5-4b`.

#### Scenario: Модель по умолчанию
- **WHEN** `LMSTUDIO_MODEL` не задан
- **AND** отправляется запрос генерации
- **THEN** поле `model` в апстрим-запросе равно `med-gemma-1.5-4b`

#### Scenario: Свой идентификатор модели
- **WHEN** `LMSTUDIO_MODEL` задан непустым значением
- **AND** отправляется запрос генерации
- **THEN** поле `model` в апстрим-запросе равно этому значению

### Requirement: Недоступность апстрима
Если LM Studio не принимает соединения, система SHALL завершить запрос чата с HTTP 503 и JSON `code` `llm_unavailable`.

#### Scenario: Соединение отклонено
- **WHEN** хост LM Studio отклоняет соединение
- **AND** клиент отправляет `POST /api/v1/chat`
- **THEN** система возвращает HTTP 503
- **THEN** JSON-тело содержит `"code": "llm_unavailable"`

### Requirement: Таймаут апстрима
Если запрос к LM Studio превышает настроенный таймаут, система SHALL завершить запрос чата с HTTP 504 и JSON `code` `llm_timeout`.

#### Scenario: Медленная модель
- **WHEN** LM Studio не завершает запрос чата за настроенный таймаут
- **AND** клиент отправляет нестриминговый `POST /api/v1/chat`
- **THEN** система возвращает HTTP 504
- **THEN** JSON-тело содержит `"code": "llm_timeout"`

### Requirement: Ошибка апстрима
Если LM Studio возвращает HTTP-ошибку (в том числе неизвестный идентификатор модели), система SHALL завершить запрос чата с HTTP 502 и JSON `code` `llm_error`. Текст для клиента MUST NOT содержать сырые секреты апстрима.

#### Scenario: Неизвестная модель
- **WHEN** LM Studio отвечает, что модель не найдена или не загружена
- **AND** клиент отправляет `POST /api/v1/chat`
- **THEN** система возвращает HTTP 502
- **THEN** JSON-тело содержит `"code": "llm_error"`
- **THEN** `message` — короткое пояснение для человека

### Requirement: Настраиваемый таймаут запроса
Система SHALL применять числовой таймаут к вызовам LM Studio. Таймаут по умолчанию SHALL быть 120 секунд. Значение SHALL переопределяться через `LMSTUDIO_TIMEOUT_SECONDS`.

#### Scenario: Таймаут по умолчанию
- **WHEN** `LMSTUDIO_TIMEOUT_SECONDS` не задан
- **THEN** апстрим-вызовы чата используют таймаут 120 секунд

### Requirement: Генерация только через программный слой
Система SHALL выполнять генерацию чата только через программный слой ассистента, нацеленный на настроенный OpenAI-совместимый URL LM Studio. HTTP-слой MUST NOT отправлять отдельные запросы chat completions в обход этого слоя. Проверка готовности (`GET /ready`) SHALL обращаться к LM Studio без прогона программы чата.

#### Scenario: Чат не обходит программу
- **WHEN** клиент отправляет корректный `POST /api/v1/chat`
- **THEN** генерация выполняется программным слоем ассистента
- **THEN** HTTP-слой не шлёт параллельный самостоятельный запрос chat completions

#### Scenario: Ready без генерации
- **WHEN** клиент вызывает `GET /ready`
- **THEN** система проверяет доступность LM Studio без прогона программы чата

### Requirement: Исходящий запрос совместим с сервером модели
Система SHALL приводить запрос генерации к виду, который принимают локальный OpenAI-совместимый сервер и шаблон загруженной модели. Последовательность ролей в сообщениях запроса SHALL чередоваться: два сообщения одной роли подряд MUST NOT отправляться. Система MUST NOT объявлять серверу модели режимы структурированного вывода, которых тот не поддерживает.

#### Scenario: Роли чередуются
- **WHEN** программный слой формирует несколько сообщений подряд от одной роли
- **THEN** исходящий запрос содержит их объединёнными в одно сообщение
- **THEN** в последовательности ролей исходящего запроса нет двух одинаковых ролей подряд

#### Scenario: Неподдерживаемый режим вывода не запрашивается
- **WHEN** система отправляет запрос генерации
- **THEN** запрос не содержит режим структурированного вывода `json_object`

#### Scenario: Отказ сервера модели из-за формы запроса
- **WHEN** сервер модели отклоняет запрос из-за его формы
- **THEN** система возвращает клиенту ошибку с машиночитаемым кодом
- **THEN** тела сообщений чата не попадают в лог

### Requirement: Совместимость модели проверяется до первого запроса врача
Система SHALL проверять, что настроенная модель принимает запрос со схемой ответа, не дожидаясь запроса чата от пользователя. Если сервер модели доступен, но модель такой запрос не принимает, система MUST NOT продолжать работу молча. Недоступность сервера модели MUST NOT препятствовать запуску процесса: это состояние уже описано проверкой готовности.

#### Scenario: Модель не поддерживает схему ответа
- **WHEN** сервер модели доступен
- **AND** настроенная модель отклоняет запрос со схемой ответа
- **THEN** система сообщает о несовместимости конфигурации при запуске
- **THEN** система не остаётся в состоянии, где первый же запрос чата завершится ошибкой

#### Scenario: Сервер модели недоступен при запуске
- **WHEN** сервер модели не отвечает во время запуска
- **THEN** процесс запускается
- **THEN** `GET /ready` сообщает о неготовности

#### Scenario: Модель подменили после запуска
- **WHEN** в сервере модели загружена другая модель, не принимающая схему ответа
- **AND** клиент вызывает `GET /ready`
- **THEN** система сообщает о неготовности
- **THEN** тело ответа содержит машиночитаемый код

### Requirement: Рассуждение модели не покидает сервер
Если сервер модели возвращает рассуждение отдельно от ответа, система MUST NOT включать это рассуждение в ответ API. Система SHALL позволять сохранять рассуждение для отладки, и такое сохранение SHALL быть выключено по умолчанию и включаться явной настройкой.

#### Scenario: Рассуждение не отдаётся клиенту
- **WHEN** сервер модели вернул ответ вместе с рассуждением
- **THEN** ответ API содержит только текст ассистента
- **THEN** рассуждение модели в ответе отсутствует

#### Scenario: Отладочное сохранение выключено по умолчанию
- **WHEN** настройка сохранения рассуждения не задана
- **AND** выполняется запрос чата
- **THEN** рассуждение модели не записывается

#### Scenario: Отладочное сохранение включено явно
- **WHEN** настройка сохранения рассуждения включена
- **AND** выполняется запрос чата
- **THEN** рассуждение модели сохраняется отдельно от журнала обращений
