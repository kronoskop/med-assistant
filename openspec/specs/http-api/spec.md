# http-api Specification

## Purpose

Описывает Python HTTP API ассистента: запуск сервиса, проверка живости, конфигурация из окружения и единый JSON-контракт ошибок. Веб-интерфейса нет.

## Requirements

### Requirement: HTTP-сервис без веб-интерфейса
Система SHALL предоставлять JSON HTTP API и MUST NOT отдавать прикладной веб-интерфейс (HTML-страницы для конечных пользователей).

#### Scenario: Ответ JSON API
- **WHEN** клиент отправляет `GET /health`
- **THEN** тип содержимого ответа — JSON
- **THEN** тело ответа не является HTML-документом

#### Scenario: Неизвестный путь
- **WHEN** клиент запрашивает путь, которого нет в API
- **THEN** система возвращает HTTP 404
- **THEN** тело ответа — JSON-объект ошибки

### Requirement: Проверка живости процесса
Система SHALL предоставлять `GET /health`, который сообщает о живости процесса и MUST NOT вызывать языковую модель.

#### Scenario: Процесс запущен
- **WHEN** HTTP-процесс работает
- **AND** клиент вызывает `GET /health`
- **THEN** система возвращает HTTP 200
- **THEN** JSON-тело содержит `"status": "ok"`

### Requirement: Готовность зависит от локального сервера модели
Система SHALL предоставлять `GET /ready`, который сообщает, доступен ли настроенный endpoint LM Studio.

#### Scenario: LM Studio доступен
- **WHEN** настроенный базовый URL LM Studio отвечает
- **AND** клиент вызывает `GET /ready`
- **THEN** система возвращает HTTP 200
- **THEN** JSON-тело содержит `"status": "ready"`

#### Scenario: LM Studio недоступен
- **WHEN** настроенный базовый URL LM Studio не отвечает
- **AND** клиент вызывает `GET /ready`
- **THEN** система возвращает HTTP 503
- **THEN** JSON-тело содержит `"status": "not_ready"`
- **THEN** JSON-тело содержит машиночитаемый код ошибки

### Requirement: Конфигурация из окружения
Система SHALL загружать настройки из переменных окружения (с задокументированными значениями по умолчанию): хост и порт HTTP, базовый URL LM Studio, идентификатор модели и таймаут запроса.

#### Scenario: Локальный LM Studio по умолчанию
- **WHEN** URL LM Studio и идентификатор модели не заданы в окружении
- **THEN** система использует базовый URL `http://127.0.0.1:1234/v1`
- **THEN** система использует идентификатор модели `med-gemma-1.5-4b`

#### Scenario: Переопределение через окружение
- **WHEN** заданы `LMSTUDIO_BASE_URL` и `LMSTUDIO_MODEL`
- **THEN** система использует эти значения для вызовов модели

### Requirement: Единый формат JSON-ошибок
Система SHALL возвращать ошибки как JSON-объекты с полями `code` (стабильная машиночитаемая строка) и `message` (текст для человека). Ошибки валидации SHALL использовать HTTP 422 или 400.

#### Scenario: Некорректное JSON-тело
- **WHEN** клиент отправляет POST с телом, которое не является валидным JSON
- **THEN** система возвращает HTTP 400 или 422
- **THEN** тело содержит `code` и `message`

### Requirement: Без аутентификации в этой версии
Система SHALL принимать запросы API без учётных данных. Аутентификация медперсонала вне объёма этого изменения.

#### Scenario: Запрос без заголовка Authorization
- **WHEN** клиент вызывает `GET /health` или `POST /api/v1/chat` без заголовка `Authorization`
- **THEN** запрос не отклоняется из-за отсутствия учётных данных
