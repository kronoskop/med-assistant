# chat Specification

## Purpose

Описывает чат с ИИ-ассистентом для медперсонала: история сообщений, системный промпт, синхронный и потоковый ответ. Клиент передаёт историю сам; сервер диалоги не хранит.

## Requirements

### Requirement: Эндпоинт чата
Система SHALL принимать `POST /api/v1/chat` с JSON-телом: `messages` (непустой массив `{ "role": "user" | "assistant", "content": string }`) и необязательный `stream` (boolean, по умолчанию `false`).

#### Scenario: Успешный ответ без потока
- **WHEN** клиент отправляет `POST /api/v1/chat` хотя бы с одним сообщением пользователя и без `stream` либо с `stream: false`
- **AND** языковая модель возвращает ответ
- **THEN** система возвращает HTTP 200
- **THEN** JSON-тело содержит `message.role` равным `"assistant"`
- **THEN** JSON-тело содержит `message.content` как непустую строку

#### Scenario: Пустой массив сообщений
- **WHEN** клиент отправляет `POST /api/v1/chat` с `"messages": []`
- **THEN** система возвращает HTTP 400 или 422
- **THEN** тело — JSON-ошибка с `code` и `message`

#### Scenario: Недопустимая роль
- **WHEN** клиент отправляет сообщение, у которого `role` не `user` и не `assistant`
- **THEN** система возвращает HTTP 400 или 422

#### Scenario: Пустое содержимое
- **WHEN** клиент отправляет сообщение с пустым `content` или только из пробелов
- **THEN** система возвращает HTTP 400 или 422

### Requirement: Сервер подставляет системный промпт
Система SHALL применять серверную инструкцию роли медицинского ассистента через программный слой генерации. Инструкция MUST сообщать, что ассистент поддерживает врача и MUST NOT подменять профессиональное суждение или выдавать диагноз как окончательное клиническое решение. Инструкция MUST NOT фиксировать специализацию по отделению или профилю. Системные сообщения от клиента MUST NOT заменять эту инструкцию. История из тела запроса SHALL передаваться во вход программы. Форма промпта на стороне модели не обязана совпадать с сырым массивом OpenAI-сообщений с первым `role: system`.

#### Scenario: Клиент шлёт только сообщения пользователя
- **WHEN** клиент отправляет корректный запрос чата только с сообщениями пользователя
- **THEN** программный слой генерации включает серверную инструкцию медицинского ассистента
- **THEN** сообщения из запроса передаются во вход программы

#### Scenario: Клиент пытается подменить системный промпт
- **WHEN** клиент включает сообщение с `role` `system`
- **THEN** система отклоняет запрос с HTTP 400 или 422
- **THEN** серверная инструкция программы не подменяется

### Requirement: Чат без хранения на сервере
Система MUST NOT сохранять историю чата. Каждый запрос MUST быть самодостаточным: клиент SHALL передать полный список сообщений, нужный для контекста.

#### Scenario: Повторный запрос без прошлых сообщений
- **WHEN** клиент отправляет следующее сообщение пользователя без предыдущих реплик в `messages`
- **THEN** вызов модели использует только системный промпт и сообщения из этого запроса
- **THEN** система не ищет более ранние диалоги

### Requirement: Потоковые ответы
Если `stream` равен `true`, система SHALL вернуть HTTP 200 с `Content-Type` `text/event-stream` и отдавать текст ассистента событиями Server-Sent Events. После последнего токена поток MUST завершиться терминальным событием.

#### Scenario: Успешный поток
- **WHEN** клиент отправляет `POST /api/v1/chat` с `"stream": true` и корректным сообщением пользователя
- **AND** языковая модель стримит токены
- **THEN** статус ответа — 200
- **THEN** тип содержимого — `text/event-stream`
- **THEN** клиент получает одно или несколько событий с фрагментами текста ассистента
- **THEN** поток завершается терминальным событием done

#### Scenario: Поток при недоступной модели
- **WHEN** клиент запрашивает потоковый чат
- **AND** сервер языковой модели недоступен
- **THEN** система не возвращает успешный SSE-поток текста ассистента
- **THEN** клиент получает ошибку (HTTP 503 или SSE-событие ошибки с тем же контрактом `code`)

### Requirement: Только текст в этой версии
Система SHALL принимать `content` только как текстовые строки. Изображения и мультимодальные полезные нагрузки MUST отклоняться.

#### Scenario: Нетекстовое содержимое
- **WHEN** клиент отправляет содержимое сообщения, которое не является простой строкой (например массив частей или изображение)
- **THEN** система возвращает HTTP 400 или 422

### Requirement: Клиническая оговорка в ответах API
Ответы чата без потока SHALL содержать стабильную строку `disclaimer`: ответ — поддержка решения врача, не диагноз и не замена профессионального суждения.

#### Scenario: Оговорка присутствует
- **WHEN** нестриминговый запрос чата успешен
- **THEN** JSON-тело содержит непустое поле `disclaimer`

### Requirement: Ответ опирается на извлечённые фрагменты
Система SHALL строить ответ чата на фрагментах, отобранных из корпуса под вопрос врача, и SHALL возвращать использованные фрагменты вместе с текстом ответа. Ответ MUST NOT строиться на памяти модели, когда относящихся фрагментов не нашлось.

#### Scenario: Фрагменты найдены
- **WHEN** для вопроса врача отобраны относящиеся фрагменты
- **THEN** ответ построен на этих фрагментах
- **THEN** ответ API содержит использованные фрагменты с указанием документа и места в нём

#### Scenario: Фрагменты не найдены
- **WHEN** для вопроса врача относящихся фрагментов не нашлось
- **THEN** ответ сообщает, что в корпусе ничего не найдено
- **THEN** ответ не содержит клинических утверждений по существу вопроса

### Requirement: Ссылка подтверждает утверждение только документом основы
Ссылка при утверждении ответа SHALL указывать на фрагмент документа основы. Документы подкрепления SHALL возвращаться отдельным списком и MUST NOT использоваться как подтверждение конкретного утверждения. Ответ SHALL сообщать, что при расхождении приоритет остаётся за документом основы.

#### Scenario: Ответ опирается на основу и сопровождается подкреплением
- **WHEN** по вопросу найдены документы обоих уровней
- **THEN** утверждения ответа подтверждаются фрагментами документов основы
- **THEN** документы подкрепления возвращаются отдельно от подтверждающих фрагментов

#### Scenario: Найдено только подкрепление
- **WHEN** по вопросу найдены документы подкрепления, но нет ни одного документа основы
- **THEN** ответ не содержит утверждений, поданных как подтверждённые
- **THEN** врачу сообщается, что в документах учреждения по этому вопросу ничего не найдено

### Requirement: Ссылки на фрагменты проверяются
Система SHALL сверять фрагменты, на которые ссылается модель, с фрагментами, действительно отобранными для этого вопроса. Ссылка на фрагмент, которого не было среди отобранных, MUST NOT попадать в ответ.

#### Scenario: Модель сослалась на несуществующий фрагмент
- **WHEN** модель ссылается на фрагмент, отсутствующий среди отобранных
- **THEN** эта ссылка в ответ не попадает

#### Scenario: Все ссылки подтверждены
- **WHEN** модель ссылается только на отобранные фрагменты
- **THEN** ответ содержит эти ссылки
- **THEN** каждая ссылка сопоставима с документом и местом в нём
