## Purpose

Прикладной веб-интерфейс ассистента для медперсонала: диалог с локальной моделью поверх существующего API, с честным разделением того, что система знает, и того, чего она не знает. Задаёт наблюдаемое поведение интерфейса — поток, состояние сервиса, ошибки, владение историей и правила подачи клинических материалов.

## ADDED Requirements

### Requirement: Диалог с потоковым ответом
Интерфейс SHALL вести диалог через существующий эндпоинт чата в потоковом режиме и SHALL отображать текст ответа по мере поступления. Интерфейс SHALL позволять прервать поток до его завершения и MUST NOT терять при этом уже полученную часть ответа. Признаком успешно полученного ответа SHALL считаться только явное завершение потока: ответ, поток которого оборвался, MUST NOT предъявляться врачу как полный.

#### Scenario: Ответ поступает по частям
- **WHEN** врач отправил вопрос и модель начала отвечать
- **THEN** интерфейс дописывает текст ответа по мере поступления частей
- **THEN** интерфейс показывает индикатор незавершённости ответа

#### Scenario: Врач прерывает ответ
- **WHEN** ответ ещё генерируется
- **AND** врач нажимает «Стоп»
- **THEN** интерфейс прекращает запрос
- **THEN** полученная часть ответа остаётся в ленте и помечена как прерванная

#### Scenario: Поток завершён
- **WHEN** сервер сообщил о завершении потока
- **THEN** индикатор незавершённости исчезает
- **THEN** становятся доступны действия над ответом

#### Scenario: Поток оборвался без признака завершения
- **WHEN** поток прекратился без признака нормального завершения
- **AND** врач не останавливал ответ сам
- **THEN** интерфейс сообщает о сбое генерации
- **THEN** интерфейс не выдаёт оборванный текст за полный ответ
- **THEN** становится доступен повтор запроса

### Requirement: Историей диалога владеет клиент
Сервер не хранит историю, поэтому интерфейс SHALL хранить список сообщений на стороне клиента и SHALL передавать его в каждом запросе. Интерфейс MUST NOT сохранять содержимое диалогов за пределами текущей вкладки браузера и SHALL сообщать врачу, что сервер диалоги не хранит.

#### Scenario: Продолжение диалога
- **WHEN** врач задаёт второй вопрос в том же диалоге
- **THEN** запрос содержит предыдущие сообщения диалога

#### Scenario: Перезагрузка страницы
- **WHEN** врач перезагружает страницу
- **THEN** лента диалога пуста
- **THEN** содержимое прошлых диалогов недоступно

#### Scenario: Врач видит, где живёт история
- **WHEN** интерфейс открыт
- **THEN** в интерфейсе присутствует пометка о том, что сервер диалоги не хранит

### Requirement: Интерфейс не приписывает ответу модели источники
Модель возвращает свободный текст без сведений о происхождении утверждений. Интерфейс MUST NOT показывать ссылку на документ как источник конкретного фрагмента ответа модели. Интерфейс SHALL показывать ссылки на клинические руководства как ориентир для сверки и SHALL подписывать их так, чтобы это не читалось как источник ответа.

#### Scenario: Свободный вопрос
- **WHEN** врач задаёт вопрос вне курируемых тем
- **AND** модель вернула ответ
- **THEN** фрагменты ответа не сопровождаются ссылками-сносками
- **THEN** интерфейс показывает ссылку на действующие протоколы центра как ориентир для сверки

#### Scenario: Подпись панели руководств
- **WHEN** интерфейс показывает список клинических руководств
- **THEN** подпись описывает их как материалы для сверки
- **THEN** подпись не утверждает, что документы являются источником полученного ответа

### Requirement: Признаки тревоги только из курируемого списка
Блок признаков тревоги называет пороговые значения и предписывает действие, поэтому интерфейс MUST NOT формировать его из вывода модели — ни генерацией, ни разбором текста ответа. Интерфейс SHALL показывать блок только тогда, когда вопрос сопоставлен с курируемой темой, и SHALL указывать протокол в качестве источника.

#### Scenario: Вопрос по курируемой теме
- **WHEN** вопрос врача сопоставлен с курируемой темой
- **THEN** интерфейс показывает признаки тревоги из курируемого списка этой темы
- **THEN** подпись блока указывает протокол как источник, а не модель

#### Scenario: Вопрос вне курируемых тем
- **WHEN** вопрос врача не сопоставлен ни с одной курируемой темой
- **THEN** блок признаков тревоги отсутствует

#### Scenario: Ответ модели содержит перечень признаков
- **WHEN** модель сама перечислила признаки тревоги в тексте ответа
- **THEN** интерфейс не извлекает их в блок признаков тревоги
- **THEN** текст остаётся частью обычного ответа модели

### Requirement: Локальный контент интерфейса отличим от ответа модели
Часть карточек — справочный текст самого интерфейса, а не вывод модели. Интерфейс SHALL помечать такой контент видимой подписью и MUST NOT передавать его в модель как реплики ассистента.

#### Scenario: Справочная карточка в ленте
- **WHEN** интерфейс добавляет в ленту собственную справочную карточку
- **THEN** карточка помечена как справка интерфейса

#### Scenario: Последующий запрос
- **WHEN** после справочной карточки врач задаёт следующий вопрос
- **THEN** текст карточки отсутствует в списке сообщений запроса

### Requirement: Состояние сервиса и ошибки видны врачу
Интерфейс SHALL показывать состояние готовности сервиса по данным эндпоинта готовности и SHALL отображать ошибки API человекочитаемо, сохраняя машиночитаемый код для диагностики.

#### Scenario: Модель недоступна
- **WHEN** локальный сервер модели не отвечает
- **THEN** интерфейс показывает состояние недоступности
- **THEN** сообщение об ошибке содержит машиночитаемый код

#### Scenario: Превышено время ожидания
- **WHEN** запрос к модели завершился по таймауту
- **THEN** интерфейс сообщает об этом врачу отдельно от других ошибок
- **THEN** ранее полученные сообщения диалога остаются в ленте

#### Scenario: Сервис готов
- **WHEN** локальный сервер модели отвечает
- **THEN** интерфейс показывает состояние готовности

### Requirement: Язык интерфейса не меняет язык модели
Интерфейс SHALL поддерживать переключение языка интерфейса между русским, узбекским и английским. Переключение MUST NOT заявлять или подразумевать смену языка модели.

#### Scenario: Переключение языка
- **WHEN** врач выбирает другой язык интерфейса
- **THEN** элементы интерфейса отображаются на выбранном языке

#### Scenario: Язык ответа
- **WHEN** язык интерфейса изменён
- **THEN** интерфейс не утверждает, что модель будет отвечать на этом языке

### Requirement: Предупреждение о персональных данных
Интерфейс SHALL постоянно показывать предупреждение о недопустимости ввода имён и идентификаторов пациентов.

#### Scenario: Предупреждение на экране
- **WHEN** интерфейс открыт
- **THEN** предупреждение о недопустимости ввода персональных данных пациента видно врачу

### Requirement: Работоспособность без доступа в интернет
Целевая машина работает с локальной моделью и может не иметь доступа в интернет. Интерфейс SHALL оставаться пригодным к работе без внешней сети: элементы управления и значки SHALL отображаться, вёрстка MUST NOT разрушаться.

#### Scenario: Машина без доступа в интернет
- **WHEN** внешняя сеть недоступна
- **AND** врач открывает интерфейс
- **THEN** значки и элементы управления отображаются
- **THEN** вёрстка экрана сохраняется
