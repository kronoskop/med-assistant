## REMOVED Requirements

### Requirement: HTTP-сервис без веб-интерфейса
**Reason**: Ассистент предназначен для медперсонала, а работать с ним можно было только через `curl` и служебный `/docs`. Прототипу нужен прикладной интерфейс, макет которого готов и построен под существующие эндпоинты.

**Migration**: Заменено требованием «HTTP-сервис отдаёт веб-интерфейс на отдельном префиксе». JSON-контракт на путях API и формат ошибок не меняются: клиенты, работающие с `/health`, `/ready` и `/api/v1/chat`, правок не требуют.

## ADDED Requirements

### Requirement: HTTP-сервис отдаёт веб-интерфейс на отдельном префиксе
Система SHALL предоставлять JSON HTTP API и SHALL отдавать прикладной веб-интерфейс на выделенном префиксе пути. Пути API MUST NOT возвращать HTML, а отдача интерфейса MUST NOT изменять формат ответов и ошибок на путях API.

#### Scenario: Ответ JSON API
- **WHEN** клиент отправляет `GET /health`
- **THEN** тип содержимого ответа — JSON
- **THEN** тело ответа не является HTML-документом

#### Scenario: Отдача веб-интерфейса
- **WHEN** клиент открывает префикс веб-интерфейса
- **THEN** система возвращает HTTP 200
- **THEN** тип содержимого ответа — HTML

#### Scenario: Неизвестный путь вне префикса интерфейса
- **WHEN** клиент запрашивает путь, которого нет ни в API, ни в веб-интерфейсе
- **THEN** система возвращает HTTP 404
- **THEN** тело ответа — JSON-объект ошибки с полями `code` и `message`

#### Scenario: Несуществующий файл внутри префикса интерфейса
- **WHEN** клиент запрашивает несуществующий путь внутри префикса веб-интерфейса
- **THEN** система возвращает HTTP 404
- **THEN** тело ответа — JSON-объект ошибки с полями `code` и `message`
