## Why

Нужен первый рабочий контур ИИ-ассистента для медперсонала: простой Python-бэкенд с HTTP API, без веб-интерфейса. Модель `med-gemma-1.5-4b` уже крутится локально в LM Studio — приложение должно ходить в неё, а не в облако.

## What Changes

- Появляется Python HTTP API (чат и проверка живости сервиса).
- Бэкенд вызывает локальную MedGemma через OpenAI-совместимый API LM Studio.
- Ответы ассистента идут с системным промптом для медперсонала и с оговоркой, что это поддержка решения, а не диагноз. Специализации по отделению нет.
- Веб-интерфейса, авторизации, хранения диалогов и интеграции с МИС в этом изменении нет.

## Capabilities

### New Capabilities

- `http-api`: HTTP-сервис на Python — запуск, health-check, конфиг из окружения, единый контракт ошибок.
- `chat`: чат с ассистентом — история сообщений, системный промпт для медперсонала без узкой специализации, синхронный ответ и потоковая выдача.
- `llm-gateway`: клиент к локальному LM Studio (модель `med-gemma-1.5-4b`), таймауты и понятные ошибки, если модель или сервер недоступны.

### Modified Capabilities

- Нет существующих спецификаций.

## Impact

- Репозиторий сейчас пустой (только OpenSpec) — это первый прикладной код.
- Новые зависимости: веб-фреймворк Python, OpenAI-совместимый клиент, конфиг из env.
- Внешняя зависимость: LM Studio на машине разработчика/сервера с загруженной `med-gemma-1.5-4b`.
- Клиенты (curl, будущий фронт) получают REST API; облачные LLM не используются.
