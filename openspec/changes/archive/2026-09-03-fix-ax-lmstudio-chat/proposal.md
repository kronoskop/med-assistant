## Why

Чат не работает с живой моделью. `POST /api/v1/chat` против запущенной LM Studio с `medgemma-1.5-4b-it` возвращает `502 llm_error` — на любой запрос, всегда.

Дефект приехал с изменением `integrate-ax-dspy` и не был замечен, потому что все 11 тестов `tests/test_llm.py` подменяют транспорт: путь до реальной LM Studio не проверялся ни разу. Набор тестов проходит полностью при полностью нерабочем чате.

Причин три, и они вскрываются одна за другой:

1. `app/llm.py` объявляет `structuredOutputModes: ["json_object"]`, Ax шлёт `response_format: {"type": "json_object"}`, LM Studio отвечает `'response_format.type' must be 'json_schema' or 'text'`.
2. Ax формирует последовательность ролей `system, user, user` — два user-сообщения подряд. Шаблон Gemma требует строгого чередования и отвечает HTTP 400 `Conversation roles must alternate`.
3. Даже когда запрос проходит, MedGemma отвечает свободным рассуждением (`thought…`), а не JSON, которого требует типизированная сигнатура Ax, — разбор ответа падает.

## What Changes

- Клиент перестаёт объявлять неподдерживаемый режим структурированного вывода: LM Studio получает запрос без `response_format` от самого Ax.
- Перед отправкой подряд идущие сообщения одной роли объединяются в одно — последовательность ролей становится совместимой с шаблоном Gemma.
- Генерация принуждается к структуре через `response_format` типа `json_schema`, построенный по выходным полям сигнатуры: модель возвращает валидный JSON, а не рассуждение.
- Появляется тест, проверяющий форму реального исходящего запроса (чередование ролей, наличие схемы, отсутствие `json_object`), а не только факт вызова.
- Совместимость модели проверяется до первого запроса врача: при старте и в `GET /ready`. Недоступная LM Studio старту не мешает, модель, не принимающая схему, останавливает процесс.
- Рассуждение модели (`reasoning_content`) можно сохранять для отладки — отдельным логгером, по умолчанию выключенным. В ответ API рассуждение не попадает никогда.
- Внешний HTTP-контракт чата, `disclaimer` и существующие коды ошибок не меняются; добавляется код несовместимости модели.

## Capabilities

### Modified Capabilities

- `llm-gateway`: исходящий запрос к локальному OpenAI-совместимому серверу приводится к виду, который принимают LM Studio и шаблон модели; требования к кодам ошибок и таймаутам не меняются.
- `ax-programs`: структура ответа обеспечивается схемой на стороне сервера модели, а не надеждой на то, что модель сама вернёт JSON по текстовой инструкции.

## Impact

- Код: `app/llm.py`, тесты `tests/test_llm.py`.
- API: без breaking changes для `POST /api/v1/chat`, `GET /health`, `GET /ready`.
- Зависимости не добавляются. Появляется переменная окружения для включения отладочного лога рассуждения.
- Разблокирует задачи 3.1, 3.2 и 3.7 изменения `add-web-ui`: проверить поток, остановку и обрыв потока без работающего чата нельзя.
- Требование к среде: модель, загруженная в LM Studio, должна поддерживать structured output по схеме. Для `medgemma-1.5-4b-it` проверено.
