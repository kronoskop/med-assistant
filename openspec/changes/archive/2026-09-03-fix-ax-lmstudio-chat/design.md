## Context

`integrate-ax-dspy` перевёл генерацию на Ax, но проверялся только на подменённом транспорте. При первом запуске против живой LM Studio с `medgemma-1.5-4b-it` чат не работает вовсе.

Диагностика выполнена перехватом исходящего запроса через существующий хук `transport` в `LLMClient`. Ax отправляет:

```
ключи запроса: ['messages', 'model', 'temperature']
роли:          ['system', 'user', 'user']
```

Три отказа, каждый следующий вскрывается после устранения предыдущего:

| Что отправляется | Ответ LM Studio |
|---|---|
| `response_format: {"type": "json_object"}` | `'response_format.type' must be 'json_schema' or 'text'` |
| роли `system, user, user` | HTTP 400 `Conversation roles must alternate user/assistant/...` |
| запрос без `response_format` | HTTP 200, но в теле рассуждение `thought…`, а не JSON — разбор падает |

Проверено, что дело не в модели: прямой запрос в LM Studio с ролями `system` + `user` отрабатывает нормально, а `response_format: {"type":"json_object"}` отклоняется самой LM Studio независимо от Ax.

## Goals / Non-Goals

**Goals**

- Чат работает против реальной LM Studio с MedGemma.
- Ответ модели структурирован гарантированно, а не по договорённости в тексте промпта.
- Регрессия ловится тестом, который смотрит на форму исходящего запроса.

**Non-Goals**

- Отказ от Ax и возврат к прямому OpenAI-клиенту.
- Поддержка облачных провайдеров и моделей без structured output.
- Изменение системного промпта, внешнего контракта и кодов ошибок.
- Оптимизация качества ответов, подбор температуры, GEPA.

## Decisions

### 1. Совместимость обеспечивается на границе исходящего запроса

Все три отказа — свойства конкретной пары «LM Studio + шаблон Gemma», а не логики ассистента. Поэтому правка делается там, где запрос уходит наружу, и не протекает ни в сигнатуру программы, ни в промпт, ни в роутеры.

Хук `transport` для этого уже существует и используется тестами — он становится штатной точкой нормализации, а не только тестовой.

### 2. `structuredOutputModes: ["text"]` вместо `["json_object"]`

Объявление `json_object` — прямая причина первого отказа: Ax верит ему и шлёт режим, которого у LM Studio нет. В режиме `text` Ax не выставляет `response_format` вовсе, и запрос доходит.

### 3. Подряд идущие сообщения одной роли объединяются

Ax добавляет отдельным user-сообщением инструкцию о форме JSON, из-за чего получается `user, user`. Шаблон Gemma такую последовательность отвергает.

Склейка соседей одной роли через пустую строку сохраняет весь текст и делает последовательность чередующейся. Это мягче, чем выбрасывать сообщение или переносить инструкцию в системное: ни один фрагмент промпта не теряется.

### 4. Структура ответа принуждается схемой, а не просьбой

Ключевое решение. Без `response_format` MedGemma отвечает рассуждением, потому что это reasoning-модель: текстовая инструкция «верни ровно один JSON-объект» её не удерживает. Ожидать иного от 4B-модели — значит строить разбор на удаче.

LM Studio принимает `json_schema` и ограничивает генерацию грамматикой. Схема строится по выходным полям сигнатуры Ax, поэтому остаётся согласованной с ней автоматически, а не дублируется вручную.

Проверено на живой модели: с этой правкой ответ проходит весь путь и корректно разбирается Ax.

### 5. Тест смотрит на форму запроса, а не только на факт вызова

Дефект дожил до рабочей машины потому, что тесты проверяли `model` и `base_url`, но не то, как выглядит тело запроса. Добавляется проверка: роли чередуются, `response_format` имеет тип `json_schema`, `json_object` не встречается нигде.

Живая модель для этого по-прежнему не нужна — проверяется исходящий запрос на подменённом транспорте.

### 6. Рассуждение модели сохраняется, но выключено по умолчанию

MedGemma — reasoning-модель: помимо ответа она возвращает `reasoning_content`. Для отладки он полезен — видно, почему ответ получился таким.

Но это рассуждение о случае пациента, то есть клинический текст, а репозиторий держит правило «тела чатов не пишутся в лог». Прямая запись рассуждения это правило нарушила бы.

Поэтому: отдельный логгер (не `app.access`), выключен по умолчанию, включается явной переменной окружения. Умолчание остаётся безопасным, а тот, кто включает, делает это осознанно. Рассуждение MUST NOT попадать в ответ API ни при каких настройках: врачу нужен ответ, а не размышление модели.

### 7. Совместимость модели проверяется до первого запроса врача

Несовместимая модель сейчас обнаруживается только тогда, когда врач уже задал вопрос и получил `502`. Это худший момент для такого открытия.

Проверка — минимальный прогон со схемой ответа, различающий два случая:

- **LM Studio недоступна** — это штатное состояние (`/ready` его уже описывает): предупреждение в лог, процесс стартует. Сервер модели может подняться позже.
- **LM Studio отвечает, но модель не принимает схему** — это конфигурационная ошибка: процесс останавливается сразу с внятным сообщением.

`GET /ready` выполняет ту же проверку, поэтому модель, подменённая в LM Studio уже после старта, тоже будет поймана — и интерфейс покажет недоступность раньше, чем врач начнёт печатать.

Успешный результат проверки кешируется на минуту: интерфейс опрашивает `/ready` каждые 30 секунд, и гонять генерацию на каждый опрос незачем. Подмена модели обнаруживается в пределах этого окна. Неуспешный результат не кешируется — LM Studio может подняться в любой момент.

## Risks / Trade-offs

- **Схема привязывает к серверам, умеющим structured output.** LM Studio умеет; произвольный OpenAI-совместимый сервер — не обязательно. Взамен получаем гарантию структуры вместо надежды на послушность модели. Ограничение фиксируется в README.
- **Нормализация сообщений — компенсация чужого поведения.** Если Ax перестанет слать два user подряд, склейка станет холостой, но не вредной.
- **Ограничение грамматикой может слегка менять стиль ответа.** Для справочного ассистента приемлемо: предсказуемая форма важнее вариативности.
- **Reasoning-часть модели не показывается.** Для интерфейса это верно: врачу нужен ответ, а не размышление модели.

## Migration Plan

Правка внутри `app/llm.py`, внешний контракт не меняется — клиенты не трогаются. Откат — возврат `model_info` и снятие нормализации транспорта.
