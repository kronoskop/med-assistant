## Why

Замер на kmm (Gemma 4 E4B, 2026-11-15) показал, где теряются ответы. Поиск находит нужный документ (50 из 56), но в выдачу не попадает абзац с конкретикой. Модель честно отвечает «во фрагментах этого нет», хотя в документе ответ есть: так было с порогом гемоглобина при анемии беременных и с обследованиями при бесплодии. Векторный поиск по e5-small ищет по смыслу и пропускает абзацы, где совпадают точные слова и числа.

## What Changes

- `RETRIEVAL_MODE=hybrid`: к векторному поиску добавляется поиск по словам (BM25, `app/corpus/lexical.py`). Рейтинги сливаются по рангу (RRF).
  - Морфология ru/uz закрывается обрезкой слова до 6 букв. Служебные слова отбрасываются, числа сохраняются целиком.
  - Индекс слов строится при старте, около 1 с на 9 тыс. фрагментов; запрос обрабатывается меньше чем за 1 мс.
- `RERANKER_MODEL`: кандидатов (по умолчанию `RERANK_CANDIDATES=20`) переранжирует кросс-энкодер sentence-transformers.
  - Если модель недоступна, сервис работает без переранжирования и пишет об этом в журнал.
- Порядок кандидатов после слияния или переранжирования больше не перетасовывается по косинусу.
- В отчёте `bench retrieval` указано, в каком режиме шёл поиск.

По умолчанию остаётся `vector`, а переранжирование выключено, пока замер на kmm не покажет выигрыш.

## Impact

`app/corpus/{lexical,rerank,index,service}.py`, `app/settings.py`, `app/main.py`, `tools/bench.py`. API не меняется.
