# Уточнение ответов медиками

## Why

Система должна постоянно улучшаться силами медиков: ответ, который медик считает правильным и который подтвердили коллеги, дальше используется как есть.

## What Changes

- Вход по логину и паролю, роли: администратор, медик, наблюдатель. Учётные записи создаёт администратор; первый администратор создаётся при первом запуске.
- Правый клик по ответу → «Уточнить ответ»: медик вписывает свой ответ.
- Голосование: «Подтверждаю» / «Не согласен» (с комментарием). N подтверждений (по умолчанию 3, настраивается в админке) — принято; одно несогласие — отклонено. Автор своё не подтверждает.
- Своя формулировка: автор уточнения получает сообщение в кабинет и принимает или отклоняет её. Принял — текущее уточнение закрывается, голосование идёт заново по новой формулировке; согласие автора считается первым подтверждением.
- Принятый ответ отдаётся дословно на тот же вопрос (первый вопрос диалога), с пометкой «Проверено медиками», без поиска и без модели. Новый принятый ответ на тот же вопрос отправляет прежний в архив.
- Дообучение модели не требуется; принятые пары выгружаются в JSONL для будущего дообучения.
- Интерфейс на русском, узбекском и английском.

## Non-goals

- Само дообучение модели.
- Самостоятельная регистрация, восстановление пароля по почте.

## Impact

- Новый пакет `app/review/` (хранилище SQLite, вход, API, выдача принятых ответов), `app/static/review*.{js,css}`.
- `POST /api/v1/chat` требует входа (`AUTH_REQUIRED=false` отключает), в ответе новое поле `verified`.
- Близость по смыслу выключена по умолчанию (`VERIFIED_MIN_SCORE=0`): порог не замерен на целевой машине, замер — `tools/verified_threshold.py`.
