# med-assistant

HTTP API ИИ-ассистента для медперсонала и веб-интерфейс к нему. Модель — локальная **MedGemma** (`med-gemma-1.5-4b`) в [LM Studio](https://lmstudio.ai/download/latest/darwin/arm64?format=dmg).

Чат собирается как типизированная программа [Ax](https://axllm.dev/) (Python-пакет `axllm`) и уходит в тот же локальный LM Studio. Облачный ключ OpenAI не нужен.

Ассистент — поддержка решения врача, не диагноз. Специализации по отделению нет.

## Требования

- Python 3.12+
- [uv](https://docs.astral.sh/uv/) (или pip)
- [LM Studio](https://lmstudio.ai/download/latest/darwin/arm64?format=dmg) (macOS Apple Silicon, не Bionic) с загруженной MedGemma и включённым локальным сервером (по умолчанию `http://127.0.0.1:1234`)

## Настройка

1. В LM Studio откройте Developer и запустите сервер.
2. Скопируйте идентификатор загруженной модели (он может отличаться от `med-gemma-1.5-4b`) и запишите в `LMSTUDIO_MODEL`.
3. Скопируйте `.env.example` в `.env` и при необходимости поправьте значения.

```bash
cp .env.example .env
```

| Переменная | Значение по умолчанию |
|---|---|
| `APP_HOST` | `127.0.0.1` |
| `APP_PORT` | `8000` |
| `LMSTUDIO_BASE_URL` | `http://127.0.0.1:1234/v1` |
| `LMSTUDIO_MODEL` | `med-gemma-1.5-4b` |
| `LMSTUDIO_API_KEY` | `lm-studio` |
| `LMSTUDIO_TIMEOUT_SECONDS` | `120` |
| `LOG_MODEL_REASONING` | `false` |

По умолчанию процесс слушает только localhost. **Авторизации нет** — ни у API, ни у веб-интерфейса. Не выставляйте `APP_HOST=0.0.0.0` в открытую сеть: браузерный интерфейс делает сервис заметнее, но никакой проверки прав за ним не стоит.

Тела чатов не пишутся в лог и не уходят в облачные LLM.

**Модель должна поддерживать structured output по схеме.** Ответ модели разбирается как структурированные поля, и структура требуется схемой на стороне LM Studio, а не просьбой в промпте: reasoning-модели на текстовую инструкцию «верни JSON» отвечают рассуждением. Совместимость проверяется при запуске и в `GET /ready` — несовместимая модель обнаруживается сразу, а не ошибкой на первый вопрос врача. Если LM Studio при запуске недоступна, процесс стартует: проверка откладывается до `/ready`.

`LOG_MODEL_REASONING=true` включает отладочную запись рассуждения модели отдельным логгером. **Рассуждение содержит клинический текст запроса** — то, что врач написал о случае. По умолчанию выключено; включайте только осознанно и не на машине с реальными пациентскими данными. В ответ API рассуждение не попадает ни при каких настройках.

## Корпус документов

Ответ строится на фрагментах реальных клинических документов, а не на памяти модели.

Основу составляют **57 документов**: 51 национальный клинический протокол и стандарт лечения по акушерству и гинекологии из [официальной базы МЗ РУз](https://clinical-protocols.uz/) плюс шесть стандартов с сайта центра. Документы идут парами: «клинический протокол» — тактика прозой, «стандарт лечения» — табличная матрица обследований; для ответа важны оба, но цитировать можно только первый. Что известно о каждом документе — название, происхождение, язык, редакция, контрольная сумма и адрес источника — записано в `app/corpus/documents.json`. **Сами файлы в git не хранятся**: это чужие документы со своим правообладателем, и они тяжёлые. Каталог `corpus/` в `.gitignore`.

Наполнить корпус на новой машине:

```bash
uv run python -c "
from pathlib import Path
from app.corpus.manifest import load
from app.corpus.store import fetch_all, MANIFEST_PATH
for r in fetch_all(load(MANIFEST_PATH), Path('corpus')):
    print(r.document_id, r.language, 'ok' if r.matched else 'НЕ СОВПАЛА КОНТРОЛЬНАЯ СУММА')
"
```

Затем собрать индекс:

```bash
uv run python -c "
from pathlib import Path
from app.settings import get_settings
from app.corpus.index import build, save
from app.corpus.embed import embed_passages
s = get_settings(); frs, _ = build(s)
save(frs, embed_passages([f.text for f in frs], s), Path(s.corpus_dir))
print('фрагментов:', len(frs))
"
```

Первая сборка долгая: послойный разбор PDF нужен, чтобы отличить таблицу от прозы, и на сотне документов занимает часы. Результат кешируется в `corpus/fragments.json`, поэтому повторная сборка — доли секунды. Кеш привязан к составу корпуса и правилам нарезки: меняется манифест или параметры разбиения — разбор идёт заново сам.

### Два уровня доказательности

- **Основа** — документы центра. Только они подтверждают утверждения: у утверждения в ответе стоит сноска, ведущая к фрагменту с указанием страницы и раздела.
- **Подкрепление** — документы ВОЗ. Показываются ссылками, без цитат и без сносок. При расхождении приоритет остаётся за протоколом центра, и интерфейс говорит об этом прямо.

Ссылка, которую назвала модель, сверяется с реально отобранными фрагментами: несуществующая отбрасывается вместе со сноской. Если модель не сослалась ни на один фрагмент, ответ считается неподтверждённым и врач видит отказ, а не прозу модели.

### Уточняющие вопросы

К ответу прикладываются вопросы о сведениях, которых врач не привёл, а протокол требует учитывать. Каждый вопрос опирается на фрагмент документа основы и проходит ту же сверку, что и сноски: вопрос со ссылкой на неотобранный фрагмент отбрасывается целиком. Больше трёх вопросов не показывается.

Уточнения идут вместе с ответом, а не вместо него: врач спросил сейчас, и ответ по неполным данным полезнее отказа. К отказу они не добавляются — там подтверждать нечего.

Отдельно отмечаются противоречия внутри описания случая: два сообщённых врачом сведения, которые не могут быть верны одновременно. Показываются обе стороны цитатами. Расхождение сведений врача с пороговым значением протокола противоречием не считается — это клиническая ситуация, и решение по ней принимает врач.

### Модель эмбеддингов

По умолчанию `text-embedding-multilingual-e5-small` с префиксами `query:` / `passage:` — они обязательны для семейства E5. Выбор сделан замером на шести темах корпуса: точность top-1 на русском 5/6 против 2/6 у `nomic-embed-text-v1.5`, который на кириллице почти не различает темы.

Порог косинусной близости намеренно нулевой: у этой модели посторонний вопрос набирает столько же, сколько профильный, поэтому релевантность решает не число, а то, сослалась ли модель на фрагмент.

### Темы интерфейса

Список тем на стартовом экране собирается из манифеста:

```bash
uv run python tools/gen_topics.py
```

Тема существует, только если под ней есть документ. Формулировки вопросов курируются в `tools/gen_topics.py`, идентификаторы берутся из корпуса — разойтись молча они не могут.

## Веб-интерфейс

После `make run` интерфейс доступен по адресу:

```
http://127.0.0.1:8000/ui
```

Это клинический справочный ассистент: диалог с потоковым ответом, три языка интерфейса (русский, узбекский, английский), две плотности вёрстки и шесть курируемых тем.

Что о нём стоит знать перед использованием:

- **История диалога живёт только во вкладке браузера.** Сервер её не хранит: клиент передаёт весь список сообщений в каждом запросе. Перезагрузка страницы очищает переписку.
- **Ссылки на клинические руководства — ориентир для сверки, а не источники ответа.** Модель отвечает без ссылок на документы; интерфейс не приписывает её тексту происхождение.
- **Признаки тревоги показываются только для распознанной курируемой темы** и берутся из протокола, а не из вывода модели. На свободном вопросе блок не появляется.
- **Карточки «Где сверить» и «Консультация центра» помечены как справка интерфейса** и не отправляются в модель как её реплики.
- Язык интерфейса не меняет язык модели: она отвечает на языке вопроса.

Интерфейс работает и без доступа в интернет — значки встроены в страницу. Без сети теряются только шрифты PT Serif и Manrope, вёрстка сохраняется.

Словари, темы, признаки тревоги и подборки руководств в `app/static/data.js` выгружены из артборда Claude Design и правятся не вручную, а пересборкой:

```bash
node tools/sync_design.mjs "путь/к/Чат-бот центра.dc.html"
```

Проверка, что API живо (без вызова модели):

```bash
curl http://127.0.0.1:8000/health
```

Проверка, что LM Studio отвечает:

```bash
curl http://127.0.0.1:8000/ready
```

Чат без потока:

```bash
curl http://127.0.0.1:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Кратко напомни критерии оценки обезвоживания у ребёнка"}]}'
```

Поток SSE:

```bash
curl -N http://127.0.0.1:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -d '{"stream":true,"messages":[{"role":"user","content":"Кратко напомни критерии оценки обезвоживания у ребёнка"}]}'
```

Ответ содержит текст, признак привязки к документам (`grounded`), сноски (`sources`), документы подкрепления (`support`), уточняющие вопросы (`questions`) и отмеченные противоречия (`conflicts`). В потоке всё, кроме текста, приходит одним кадром перед `[DONE]`.

Историю диалога сервер не хранит: каждый запрос должен содержать нужный список `messages`.
